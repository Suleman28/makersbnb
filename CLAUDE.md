This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```shell
# Activate virtual environment (required for all Python commands)
source makersbnb-venv/bin/activate

# Run the app (http://localhost:5001)
python app.py

# Run all tests
pytest -sv

# Run a single test file
pytest -sv tests/test_listing_routes.py

# Run a single test by name
pytest -sv tests/test_listing_routes.py::test_get_listings_shows_seeded_listings

# Seed the development database
python seed_database.py

# Build CSS once
pnpm build:css

# Watch CSS (run alongside app.py in a separate terminal)
pnpm watch:css
```

## Architecture

**Stack:** Python/Flask backend, PostgreSQL via psycopg, Jinja2 templates, Tailwind CSS v4.

**Pattern:** Repository pattern — model classes (`lib/listing.py`, `lib/user.py`, `lib/booking.py`) hold data only; repository classes (`lib/*_repository.py`) own all SQL. Routes in `app.py` instantiate a repository per request, call it, and pass results to templates.

**Database connection:** `lib/database_connection.py` provides `DatabaseConnection` (wraps psycopg) and `get_flask_database_connection(app)` which stores one connection per Flask request in `g`. Tests set `APP_ENV=test` or `app.config['TESTING']=True` to switch to `TEST_DATABASE_URL`.

**Auth:** Session-based (`session['user_id']`). Passwords hashed with werkzeug's `generate_password_hash`/`check_password_hash`. `@app.context_processor` injects `current_user` into all templates. Route-level guards redirect unauthenticated users to `/`.

**Booking statuses:** `PENDING` → `BOOKED` or `DECLINED`. Only the listing owner (host) can approve/decline. `BookingRepository.is_available` checks for overlapping `BOOKED` (not `PENDING`) bookings before creating a new one.

**Styling:** Edit `static/src/input.css` and Jinja templates. `static/style.css` is generated by Tailwind and gitignored — never edit it directly.

## Testing

Tests use two fixtures from `tests/conftest.py`:
- `web_client` — Flask test client with `TESTING=True`
- `db_connection` — `DatabaseConnection(test_mode=True)`, connects to `TEST_DATABASE_URL`

Route tests seed the DB in an `autouse` fixture: `db_connection.seed("seeds/seed.sql")`. This drops and recreates all tables, so each test file starts clean. The `test_web_address` fixture (Playwright/xprocess) starts a real Flask server for browser tests.

## Database schema

Three tables with cascading deletes: `users` → `listings` → `bookings`. `dates_available` on `listings` is free-text (e.g. `"2027-01-01, 2028-12-12"` or `"2027-01-01 to 2028-12-12"`); the `friendly_dates` Jinja filter in `app.py` normalises display.

## Known method name discrepancy

`BookingRepository` has `update_booking_status_managed_by_host` but `app.py` calls `update_status_managed_by_host` — these are mismatched. If you see `AttributeError` on booking approval/denial, this is the cause.
